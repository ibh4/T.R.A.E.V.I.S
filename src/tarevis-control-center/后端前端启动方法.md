# 后端前端启动方法

本文档用于在本机手动启动 tarevis-control-center 项目的后端和前端，并通过前端测试 Agent/Harness 功能。

## 前提条件

- 已安装 Node.js 20 或更高版本。
- 已安装 npm 10 或更高版本。
- 项目路径为：

~~~powershell
E:\PythonProjects\Trae_CompetetionProj_202606\src\tarevis-control-center
~~~

## 首次安装依赖

如果还没有安装依赖，先分别安装前端和后端依赖。

~~~powershell
cd E:\PythonProjects\Trae_CompetetionProj_202606\src\tarevis-control-center
npm ci

cd backend
npm ci
~~~

## 启动后端

打开第一个 PowerShell 窗口，执行：

~~~powershell
cd E:\PythonProjects\Trae_CompetetionProj_202606\src\tarevis-control-center\backend

$env:QWEN_API_KEY = $env:VITE_SILICONFLOW_API_KEY
$env:QWEN_BASE_URL = "https://api.siliconflow.cn/v1"
$env:QWEN_MODEL = "deepseek-ai/DeepSeek-V3.2"
$env:CONTROL_CENTER_MODE = "mock"

npm run dev
~~~

说明：

- 当前项目沿用 Qwen 兼容客户端字段，因此后端仍读取 QWEN_API_KEY、QWEN_BASE_URL 和 QWEN_MODEL。
- 这里把已有的 VITE_SILICONFLOW_API_KEY 临时映射给后端使用。
- 实际模型请求会走硅基流动接口：https://api.siliconflow.cn/v1。
- CONTROL_CENTER_MODE=mock 适合本地手动演示和前端测试。

如果新开的 PowerShell 读不到 VITE_SILICONFLOW_API_KEY，需要先手动设置：

~~~powershell
$env:VITE_SILICONFLOW_API_KEY = "你的硅基流动 API Key"
~~~

## 启动前端

打开第二个 PowerShell 窗口，执行：

~~~powershell
cd E:\PythonProjects\Trae_CompetetionProj_202606\src\tarevis-control-center

$env:CONTROL_CENTER_PROXY_TARGET = "http://127.0.0.1:8780"

npm run dev
~~~

启动成功后，浏览器打开：

~~~text
http://127.0.0.1:5180
~~~

如果 5180 端口被占用，Vite 可能会自动切到 5181 或其他端口，请以终端输出的 Local 地址为准。

## 前端手动测试

进入前端页面后，打开 Agent 页面，可以输入类似问题：

~~~text
请查看当前项目根目录，并告诉我有哪些主要目录。
~~~

如果配置正确，后端会通过硅基流动模型调用项目只读工具，例如浏览目录、读取文件或搜索文件，并在前端返回结果。

## 检查后端状态

可以在任意 PowerShell 窗口执行：

~~~powershell
Invoke-RestMethod http://127.0.0.1:8780/api/health
Invoke-RestMethod http://127.0.0.1:8780/api/harness/status
~~~

/api/harness/status 应至少显示：

~~~json
{
  "configured": true,
  "model": "deepseek-ai/DeepSeek-V3.2"
}
~~~

注意：状态中的 provider 仍可能显示为 qwen，这是因为项目目前复用了 Qwen 兼容客户端命名；只要 baseUrl 和 model 按上文设置，实际请求会走硅基流动。

## 停止服务

分别回到后端和前端 PowerShell 窗口，按：

~~~text
Ctrl+C
~~~

如需确认端口是否已释放：

~~~powershell
Get-NetTCPConnection -State Listen -LocalPort 8780,5180 -ErrorAction SilentlyContinue
~~~

无输出通常表示端口已经释放。

## 常见问题

### 后端显示模型未配置

检查当前后端窗口中是否存在 API Key：

~~~powershell
[string]::IsNullOrWhiteSpace($env:QWEN_API_KEY)
~~~

返回 False 才表示后端进程能读到 Key。

### 前端连不上后端

检查后端是否已经启动，并确认代理目标：

~~~powershell
Invoke-RestMethod http://127.0.0.1:8780/api/health
$env:CONTROL_CENTER_PROXY_TARGET
~~~

前端窗口中的 CONTROL_CENTER_PROXY_TARGET 应为：

~~~text
http://127.0.0.1:8780
~~~

### 端口被占用

检查占用端口的进程：

~~~powershell
Get-NetTCPConnection -State Listen -LocalPort 8780,5180 -ErrorAction SilentlyContinue
~~~

确认占用进程属于本项目后，再停止对应进程或更换端口。
