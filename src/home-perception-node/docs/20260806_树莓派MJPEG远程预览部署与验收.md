# 树莓派 MJPEG 远程预览部署与验收

日期：2026-08-06

状态：软件实现与无硬件测试已完成；树莓派、CSI 摄像头和 Tailscale 真机验收待最终部署同事执行。

## 1. 交付目标

树莓派独占采集 CSI 摄像头，同时完成低帧率运动检测和 MJPEG 预览。PC 中控通过局域网或 Tailscale 读取视频，现有 HTTP/WebSocket/Cloudflare Relay 继续只传状态、事件和命令。

```text
CSI camera -> Picamera2 -> VisionWorker -> motion / sparse YOLO
                                |
                                +-> /media/preview.jpg
                                +-> /media/preview.mjpg -> PC browser
```

当前协议约定：

- `picamera2://0`：树莓派第 0 个 Picamera2 摄像头。
- `/api/health`：服务和视觉工作器能力。
- `/api/state`：摄像头状态、FPS、错误和 `preview_url`。
- `/media/preview.jpg`：最新单帧 JPEG。
- `/media/preview.mjpg`：约 5 FPS 的 MJPEG 流。
- `/ws`：结构化状态与事件，不承载视频帧。

## 2. 真机信息确认

- [ ] 记录树莓派型号、内存和 Raspberry Pi OS 版本。
- [ ] 记录摄像头实物型号；项目中的 OV5647 是当前登记的 5MP Camera Module 1 传感器型号，不应替代实机识别结果。
- [ ] 关机状态下检查 CSI 排线方向并连接摄像头。
- [ ] 树莓派和 PC 加入同一个 Tailnet，ACL 只允许需要的设备访问。
- [ ] 不在家庭路由器上公开转发 `8787` 端口。

摄像头识别以系统输出为准：

```bash
cat /etc/os-release
rpicam-hello --list-cameras
rpicam-hello -t 3000
```

如果系统只有旧命令 `libcamera-hello`，应先确认 OS 版本；不要重新启用 legacy camera stack。

## 3. 安装

Picamera2 应通过 Raspberry Pi OS 的 APT 安装，避免从 pip 安装与系统 `libcamera` 不匹配的版本。虚拟环境必须使用系统 Python，并允许读取系统包。

```bash
sudo apt update
sudo apt install -y python3-venv python3-picamera2 python3-opencv

cd /path/to/Trae_CompetetionProj_202606/src/home-perception-node
python3 -m venv --system-site-packages .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e ".[ui]"
```

仅向 PC 提供 API/MJPEG 时不需要在树莓派构建前端。需要树莓派本地触摸页面时，再在 `ui` 目录执行 `npm ci && npm run build`。

运行摄像头专用诊断：

```bash
.venv/bin/python -m tarevis_home_node doctor --profile raspberry-pi-camera
```

- [ ] `ready` 为 `true`。
- [ ] `python_package:picamera2`、`raspberry_pi_hardware` 和 `camera_device` 均通过。

## 4. 启动树莓派服务

```bash
chmod +x scripts/start-raspberry-pi-ui.sh
./scripts/start-raspberry-pi-ui.sh
```

默认参数：

```text
host=0.0.0.0
port=8787
vision_source=picamera2://0
resolution=640x480
target_fps=5
auto_start_vision=true
```

参数可通过环境变量覆盖：

```bash
TAREVIS_PORT=8877 \
TAREVIS_VISION_SOURCE=picamera2://0 \
TAREVIS_VISION_WIDTH=640 \
TAREVIS_VISION_HEIGHT=480 \
TAREVIS_VISION_FPS=5 \
./scripts/start-raspberry-pi-ui.sh
```

先在树莓派本机检查：

```bash
curl --fail http://127.0.0.1:8787/api/health
curl --fail http://127.0.0.1:8787/api/state
curl --fail --output /tmp/tarevis-preview.jpg http://127.0.0.1:8787/media/preview.jpg
file /tmp/tarevis-preview.jpg
```

## 5. Tailscale 接入

### 5.1 PC 本地 HTTP 中控

当中控由 `http://127.0.0.1:5180` 本地启动时，可以直接读取 Tailnet 内的 HTTP 服务。

树莓派：

```bash
tailscale status
tailscale ip -4
```

PC 的 `src/tarevis-control-center/.env.local`：

```dotenv
VITE_HOME_CAMERA_PREVIEW_URL=http://<pi-magicdns-name>:8787/media/preview.mjpg
```

重启中控开发服务后，进入“设备管理 -> OV5647 Camera -> 打开画面”。

### 5.2 Cloudflare HTTPS 中控

HTTPS 页面不能加载 HTTP MJPEG。推荐让家庭节点只监听本机，再由 Tailscale Serve 提供 Tailnet 内的 HTTPS：

```bash
TAREVIS_HOST=127.0.0.1 ./scripts/start-raspberry-pi-ui.sh
sudo tailscale serve --bg --https=443 http://127.0.0.1:8787
tailscale serve status
```

中控生产构建变量：

```dotenv
VITE_HOME_CAMERA_PREVIEW_URL=https://<pi-magicdns-name>/media/preview.mjpg
```

更新 Cloudflare Pages 构建变量后需要重新构建和部署前端。访问中控的 PC 仍需加入同一个 Tailnet。若浏览器启用了额外的本地网络访问限制，应在该浏览器完成一次真机授权测试。

停止 HTTPS 代理：

```bash
sudo tailscale serve --https=443 off
```

## 7. 常见问题

| 现象 | 优先检查 |
| --- | --- |
| `No cameras available` | 关机检查排线；运行 `rpicam-hello --list-cameras`；确认未启用 legacy stack。 |
| `No module named picamera2/libcamera` | 使用系统 Python 创建 `--system-site-packages` venv；Picamera2 使用 APT 安装。 |
| 摄像头无法打开 | 停止其他 Picamera2、OpenCV、MediaMTX 或 `rpicam-*` 进程，保证单一采集者。 |
| `/media/preview.jpg` 返回 503 | 查看 `/api/state` 的 `last_error`；确认视觉工作器已自动启动。 |
| HTTPS 中控显示“需要 HTTPS” | 使用 Tailscale Serve HTTPS 地址，不要配置 `http://100.x.x.x`。 |
| 画面延迟或卡顿 | 先固定 640x480、5 FPS；检查 Wi-Fi 信号和 `tailscale status` 是否为 direct。 |
