> 日期：2026-07-21

## 一、目标与边界

本轮目标是把旧项目中已经验证过的树莓派视觉、音频采集与事件输出能力，整理为一个可以独立运行的 TAREVIS 家庭感知节点。

开发顺序固定为：

```text
迁移与重构
  -> 独立模块
  -> PC 跑通
  -> 树莓派部署
  -> 最后接入 TAREVIS
```

当前阶段不修改 `src/trae-status-monitor` 的运行链路，不让新模块直接控制电子吧唧，也不依赖真实树莓派、摄像头或外部 OpenCLAW 服务。

模块职责限定为：

- 从摄像头、视频、麦克风或音频文件读取输入。
- 在本地做轻量检测、识别、过滤与去重。
- 产生带版本的结构化家庭事件。
- 将事件写入标准输出、本地日志或可替换的传输适配器。
- 为后续接入 TAREVIS 保持稳定、可测试的事件协议。

模块暂不负责：

- 电子吧唧 UI 和动画。
- 家庭事件最终优先级编排。
- 远程通知和真实家居设备控制。
- 将 OpenCLAW 作为运行必需条件。
- 医疗诊断或仅凭单帧作出确定性跌倒结论。

## 二、两个项目的代码现状

### 2.1 TAREVIS 当前已有能力

当前项目的 `src/trae-status-monitor/src/home/` 已经具备：

- 五类家庭事件类型：快递、访客、门口异常、厨房风险、疑似跌倒。
- `low / medium / high` 分级。
- `detected / local_alert_sent / waiting_ack / escalated / resolved` 状态。
- 当前最高优先级事件选择。
- WebSocket 家庭屏幕协议。
- 网页调试与电子吧唧三态降级映射。
- Mock 场景与相应测试。

但是当前数据源仍在 `src/trae-status-monitor/src/index.ts` 中固定实例化为 `MockHomeEventSource`，还没有真实家庭设备事件入口。

这说明本轮不需要重做 TAREVIS 家庭事件前台，只需实现此前刻意留空的真实感知节点。未来接入时，再将 `MockHomeEventSource` 抽象为通用事件源接口，并新增真实设备适配器。

### 2.2 旧项目实际可运行能力

以代码而不是 README 描述为准，旧项目真正实现的能力如下。

## 四、统一事件契约

感知层需要区分“原始线索”和“经过确认的业务事件”。OpenCV 运动检测不能直接伪装成快递、访客或跌倒识别。

建议基础事件示例：

```json
{
  "schema_version": "1.0",
  "event_id": "evt_xxx",
  "device_id": "pc-dev",
  "source": "vision",
  "type": "motion_detected",
  "level": "info",
  "occurred_at": "2026-07-21T12:00:00+02:00",
  "zone": "living_room",
  "confidence": null,
  "payload": {
    "camera_id": "cam_0",
    "motion_score": 0.083,
    "snapshot_path": "data/snapshots/xxx.jpg"
  }
}
```

协议原则：

- `schema_version` 用于后续兼容演进。
- `event_id` 由感知节点生成并保持唯一。
- `device_id` 标识 PC、树莓派或其他未来设备。
- `source` 描述视觉、语音、音频或 mock 来源。
- `type` 只能表达当前检测器实际证明的事实。
- `level` 对底层线索默认使用 `info`，业务事件才使用 `low / medium / high`。
- `occurred_at` 使用带时区 ISO 8601 时间。
- `confidence` 只用于有明确概率语义的模型输出，OpenCV 运动面积不得伪装成置信度。
- `payload` 保存相机、ROI、边界框、原始文本、模型信息和证据路径等扩展内容。
- 默认不在事件中嵌入原始音视频字节，避免日志和网络负担。

初期事件类型分层：

| 层级 | 事件类型示例 | 含义 |
| --- | --- | --- |
| 原始线索 | `motion_detected` | ROI 中发生显著运动 |
| 原始线索 | `speech_transcribed` | 本地音频已转写 |
| 本地路由 | `help_keyword_detected` | 转写命中求助类短语 |
| 本地路由 | `user_acknowledged` | 转写命中确认类短语 |
| 二级确认 | `person_detected` | 目标检测模型确认有人 |
| 业务候选 | `fall_suspected` | 姿态与时序规则产生疑似跌倒候选 |

在没有额外模型和时序证据前，不输出确定性的 `fall_detected`。

## 六、OpenCV 与 YOLO 决策

采用 OpenCV-first、YOLO 可插拔的混合路线。

```text
OpenCV 常驻轻量检测
        |
        | 运动触发
        v
抽取少量关键帧
        |
        v
YOLO / ONNX 二级确认
        |
        v
规则或姿态时序判断
        |
        v
结构化事件
```

原因：

- OpenCV 更适合树莓派常驻、ROI 和低成本触发。
- YOLO 更适合判断是否存在人或目标，但不应持续处理每一帧。
- 普通 YOLO 目标框不能单独证明发生跌倒。
- 跌倒判断至少需要姿态特征和跨帧状态变化。
- PC 阶段可以验证 ONNX 运行时和接口，树莓派阶段再根据性能选择 ONNX Runtime、NCNN 或其他格式。

引入模型前必须补齐：

- 模型来源与许可证。
- 输入尺寸、预处理和标签表。
- 输出后处理与 NMS。
- 最小正例、负例和误报测试。
- PC 与树莓派的延迟、CPU 和内存基准。

## 七、分阶段实施与自动提交

### Phase 0：计划固化

交付：

- 本文档。
- 明确隔离边界、迁移清单和验收顺序。

验收：

- 不修改 TAREVIS 运行代码。
- 文档位于模块专用 `docs/` 中。

### Phase 1：隔离骨架与事件契约

交付：

- 独立 `pyproject.toml` 和包结构。
- 统一事件数据模型与校验。
- mock 事件 CLI。
- stdout 与 JSONL 输出。
- 基础配置和单元测试。

验收：

- 不安装视觉和音频重依赖即可运行。
- 能生成、序列化、记录并回读事件。
- 测试不依赖网络和硬件。

### Phase 2：PC 视觉闭环

交付：

- 视频文件和摄像头输入适配器。
- OpenCV 运动检测。
- ROI、连续帧、冷却和抓拍。
- 可选浏览器调试预览。
- 生成可重复的合成测试视频。

验收：

- 先用合成视频稳定产生 `motion_detected`。
- 无运动视频不产生事件。
- 可选使用电脑摄像头人工验证。
- 不把运动事件标记成快递、访客或跌倒。

### Phase 3：PC 音频闭环

交付：

- 音频文件与麦克风输入。
- RMS、时长过滤。
- FunASR 适配器与可替换 mock 转写器。
- 求助短语、确认短语本地路由。

验收：

- 无模型时可用 mock 转写完成测试。
- 有模型时能识别音频文件。
- 麦克风采用按键或固定时长模式，不在第一版做持续窃听式采集。
- “啊”等单个模糊声音不直接升级为高风险事件。

### Phase 4：YOLO / ONNX 二级检测

交付：

- 通用 `ObjectDetector` 接口。
- mock 检测器和可选 ONNX 检测器。
- 运动触发后的稀疏推理。
- 模型元数据和基准脚本。

验收：

- 没有模型时主模块仍能正常运行。
- 目标检测结果与运动分数严格分离。
- 至少验证 person 类正例、负例和失败输入。

### Phase 5：树莓派部署

交付：

- Raspberry Pi 配置。
- 系统依赖说明。
- 摄像头、麦克风与模型诊断命令。
- 资源与稳定性基准。

验收：

- 摄像头和麦克风分别独立通过测试。
- 视觉与音频组合运行时无明显资源争用。
- 连续运行、日志轮转和异常恢复通过测试。

### Phase 6：接入 TAREVIS

本阶段不在当前隔离开发范围内，需在前五阶段稳定后单独确认。

预计工作：

- 将当前 `MockHomeEventSource` 抽象为通用接口。
- 新增真实 HTTP 或 WebSocket 事件入口。
- 将感知层事件适配成现有 `HomeEvent`。
- 保留 mock 数据源作为演示与回归测试。
- 明确设备鉴权、重试、幂等和离线状态。

## 八、测试策略

测试遵循从无硬件到有硬件的顺序：

1. 纯数据模型单元测试。
2. mock 事件端到端测试。
3. 合成视频和音频文件测试。
4. PC 摄像头和麦克风人工测试。
5. 可选模型推理测试。
6. 树莓派单设备测试。
7. 树莓派视觉与音频组合测试。
8. 最终 TAREVIS 协议集成测试。

测试素材应优先使用程序生成或明确允许进入仓库的短素材，避免提交家庭真实音视频。

## 九、依赖与配置原则

- 不沿用旧项目未锁版本的单一 `requirements.txt`。
- 核心包仅包含标准库或轻量依赖。
- 使用可选依赖组隔离 `vision`、`audio`、`asr` 和 `onnx`。
- 配置文件只保存非敏感默认值。
- token、密码、设备地址通过环境变量或本地未跟踪配置注入。
- 模型文件默认不直接进入 Git，`models/README.md` 记录来源、哈希与安装步骤。
- 运行数据、抓拍、录音和模型缓存必须加入 `.gitignore`。

## 十、风险与处理

| 风险 | 处理方式 |
| --- | --- |
| README 与代码能力不一致 | 所有验收结论以可运行代码和测试为准 |
| OpenCV 误报 | 使用中性原始事件、ROI、连续帧、冷却和二级确认 |
| 跌倒误判 | 先输出 `fall_suspected`，引入姿态和时序证据后再升级 |
| 音频误报 | RMS/VAD、短语白名单、冷却和视觉联合确认 |
| 树莓派性能不足 | 常驻 OpenCV、稀疏模型推理、降低分辨率和帧率 |
| 重依赖污染主项目 | 独立 Python 子项目和可选依赖组 |
| 隐私数据进入仓库 | 默认不提交真实音视频，运行目录全部忽略 |
| 凭据泄露 | 不迁移旧连接文档，所有凭据使用本地环境配置 |
| 与 TAREVIS 提前耦合 | 前五阶段只输出稳定事件，不修改主程序 |

旧项目 `AGENTS.md` 中存在设备连接与登录信息。这些信息不能迁移；如果旧仓库曾被公开或分享，应单独轮换相应凭据。凭据清理不属于本模块代码迁移，但属于上线前必须完成的安全工作。

## 十一、阶段完成定义

本模块在进入 TAREVIS 接入前，至少应达到：

- 一条命令可产生和记录 mock 家庭事件。
- 合成视频可以稳定触发 OpenCV 运动事件。
- 音频文件可以经 mock 或真实 ASR 产生结构化文本事件。
- 核心测试无需摄像头、麦克风、网络或云服务。
- 可选硬件或模型缺失时给出清晰错误，不影响其他能力。
- PC 配置与树莓派配置分离。
- 运行数据和敏感配置不会进入 Git。
- 每个开发阶段有独立测试结果和 Git 提交。
