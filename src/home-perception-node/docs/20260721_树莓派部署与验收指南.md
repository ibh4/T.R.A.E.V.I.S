# TAREVIS 家庭感知节点树莓派部署与验收指南

> 日期：2026-07-21<br>
> 适用模块：`src/home-perception-node`<br>
> 当前状态：部署方案已准备，真实树莓派、摄像头和麦克风尚未接入验收

## 一、验收原则

树莓派阶段必须按以下顺序分项排查：

```text
系统与 Python
  -> OpenCV
  -> 摄像头
  -> 运动检测
  -> 音频设备
  -> PCM 录音
  -> FunASR
  -> 可选 ONNX 模型
  -> 视觉与音频组合运行
  -> 长时间稳定性
```

不要第一次就同时启动摄像头、麦克风、FunASR 和 YOLO。否则依赖、设备、性能和业务问题会混在一起。

## 二、系统准备

推荐 Raspberry Pi OS 64-bit，并使用 Python 3.11 或更高版本。

```bash
sudo apt update
sudo apt install -y \
  python3-venv \
  python3-pip \
  ffmpeg \
  portaudio19-dev \
  libsndfile1 \
  libgl1 \
  libglib2.0-0 \
  v4l-utils
```

进入模块并创建虚拟环境：

```bash
cd src/home-perception-node
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
```

先安装核心和视觉：

```bash
python -m pip install -e '.[vision]'
```

需要麦克风时再安装：

```bash
python -m pip install -e '.[audio]'
```

最后单独安装 ASR：

```bash
python -m pip install -e '.[asr]'
```

如果 Torch 或 torchaudio 在树莓派上无法安装，应先确认 Raspberry Pi OS、Python 和 CPU 架构对应的 wheel，不要通过降低业务代码约束掩盖安装问题。

## 三、Doctor 检查

视觉环境：

```bash
python -m tarevis_home_node doctor --profile vision
```

完整树莓派环境：

```bash
python -m tarevis_home_node doctor --profile raspberry-pi
```

若准备了模型：

```bash
python -m tarevis_home_node doctor \
  --profile raspberry-pi \
  --model models/yolo26n.onnx \
  --labels models/coco80.txt
```

结果为 JSON。只有所有 `required: true` 的检查均为 `ok: true`，顶层 `ready` 才会是 `true`。

## 四、摄像头分项测试

确认设备：

```bash
v4l2-ctl --list-devices
ls -l /dev/video*
```

先不开预览，只验证能否读取和产生事件：

```bash
python -m tarevis_home_node --config configs/raspberry-pi.toml vision-motion \
  --source 0 \
  --camera-id cam_usb0 \
  --zone living_room \
  --width 640 \
  --height 480 \
  --target-fps 5 \
  --warmup-frames 20 \
  --min-area 1500 \
  --min-score 0.015 \
  --min-consecutive-frames 3 \
  --cooldown-seconds 4 \
  --max-events 1 \
  --sink both
```

再开启浏览器预览：

```bash
python -m tarevis_home_node --config configs/raspberry-pi.toml vision-motion \
  --source 0 \
  --preview-host 0.0.0.0 \
  --preview-port 8765 \
  --max-events 0 \
  --sink both
```

同一局域网浏览器访问 `http://<树莓派地址>:8765/`。

## 五、麦克风与 ASR 分项测试

列出输入设备：

```bash
python -m tarevis_home_node audio-devices
```

固定录音并先用 mock 转写验证文件链路：

```bash
python -m tarevis_home_node audio-record \
  --seconds 5 \
  --sample-rate 16000 \
  --channels 1 \
  --device-index <设备号> \
  --output recordings/pi-test.wav \
  --transcriber mock \
  --mock-text '我没事'
```

再运行真实 FunASR：

```bash
python -m tarevis_home_node audio-file recordings/pi-test.wav \
  --transcriber funasr \
  --funasr-model iic/SenseVoiceSmall \
  --device-target cpu \
  --sink both
```

## 六、ONNX 二级检测测试

当前仓库不分发模型。只有模型来源、许可证、标签和哈希确认后才部署到树莓派。

```bash
python -m tarevis_home_node object-benchmark \
  --model models/yolo26n.onnx \
  --labels models/coco80.txt \
  --iterations 10
```

当前 YOLO26n 候选模型已固定导出为 640 输入和传统 one-to-many 输出 `(1, 84, 8400)`。调整为 416 或 320 时必须重新导出对应固定输入模型并生成独立清单，不能只修改 CLI 参数假设模型可以缩放。

## 七、组合与稳定性测试

单项均通过后，再分别启动视觉和音频进程。第一版建议两个进程隔离，避免单个模型崩溃拖垮全部感知能力。

```bash
htop
free -h
vcgencmd measure_temp
vcgencmd get_throttled
```

至少完成：

- 连续运行 30 分钟冒烟。
- 连续运行 4 小时稳定性测试。
- 拔插摄像头后的错误表现。
- 麦克风不可用时视觉仍可运行。
- ASR 模型失败时 OpenCV 仍可运行。
- 磁盘抓拍和事件日志不会无限增长。
- 进程停止后摄像头和麦克风被释放。
